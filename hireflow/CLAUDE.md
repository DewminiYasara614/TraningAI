# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

HireFlow is a recruitment platform. The repo currently has **no application code, build, lint, or test tooling** — only:

- `design/` — static HTML design mockups (the source of truth for UI and brand).
- `.specify/` + `.claude/skills/speckit-*` — GitHub Spec Kit (v0.16.0) scaffolding for spec-driven development, configured for Claude with **PowerShell** scripts.

When application code is added, update this file with its build/test commands.

## Spec-driven workflow (Spec Kit)

Features are developed through the speckit skills, in order:
`/speckit-constitution` → `/speckit-specify` → `/speckit-clarify` (optional) → `/speckit-plan` → `/speckit-tasks` → `/speckit-analyze` (optional) → `/speckit-implement`. `/speckit-converge` appends unbuilt work back into `tasks.md`; `/speckit-checklist` and `/speckit-taskstoissues` are auxiliary.

- Feature artifacts live in `specs/NNN-short-name/` (sequential numbering); `create-new-feature.ps1` also creates a matching `NNN-short-name` git branch and sets `$env:SPECIFY_FEATURE`.
- Helper scripts are in `.specify/scripts/powershell/`; templates in `.specify/templates/`.
- `.specify/memory/constitution.md` is still the **unfilled template** — run `/speckit-constitution` before relying on it for plan gates.

## Design files (`design/`)

- `*.dc.html` files are self-contained mockups rendered by `design/support.js` (a generated runtime — do not edit it). Each has an `<x-dc>` template (with `<helmet>` for head content) and a `<script type="text/x-dc" data-dc-script>` block; `data-props` may set `$preview` width. Open the HTML directly in a browser to view.
- `ios-frame.jsx` is a copied starter providing an iOS device frame (`IOSDevice`, etc.) for mobile mockups; regenerated by tooling, so don't hand-edit.
- Existing screens: style sheet (visual language/components), Open Roles (page + wireframes), Job Application (desktop page, mobile, wireframes).

### Brand and design rules (from `design/CLAUDE.md` — apply to all UI work)

- Primary blue `#1D4ED8` (hover `#1E40AF`), grey neutrals, Inter typeface, 8px spacing grid.
- Tone: warm and professional, not corporate-stiff.
- WCAG AA contrast always; mobile-first, must work down to 360px wide.
- Reuse a small component set: button, text input, card.
- No gradients, no heavy drop-shadows.
- **Flag any request that conflicts with these rules before building it.**

## Design source

- Target screen: ./design/Job Application Page.dc.html

  Read these as HTML before generating UI. Map the visual language to CSS custom properties; no hard-coded hex.

## Conventions

- Data: browser localStorage, no backend; access via an ApplicationService backed by a StorageService
  (swappable for a real HTTP API later without touching components).
- Implement every state shown in the design (default / validating / submitting / success / error).
- Real content only - no lorem ipsum. Accessibility: labelled inputs, visible focus, sufficient contrast.
